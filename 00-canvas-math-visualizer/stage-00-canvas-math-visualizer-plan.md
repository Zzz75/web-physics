# 阶段零学习计划：Canvas + 图形数学可视化

阶段零的目标不是把数学学成考试题，而是用 Canvas 把它画出来。你要建立一种直觉：位置、方向、速度、波、插值、噪声都不是抽象公式，它们是屏幕上可观察、可调试、可解释的运动。

最终产物是一个 `Canvas Math Visualizer`。

## 阶段目标

完成阶段零后，你应该能做到：

- 用 Canvas 创建高清、响应式的绘图区域。
- 画出坐标轴、点、线、圆、箭头、文本标签。
- 用向量描述位置、方向、速度和力。
- 用三角函数做波形、圆周运动和周期动画。
- 用 Lerp / Easing 做平滑移动和参数过渡。
- 用 Noise 生成连续变化、流场和基础程序化纹理。
- 面对画面异常时，能画出调试信息并解释问题来源。

## 学习方式

每个小主题都按这个循环推进：

```text
写最小 Demo -> 画出调试信息 -> 故意制造错误 -> 解释错误 -> 修正实现
```

不要追求代码一开始优雅。阶段零优先追求“看见”和“解释”。

## 第 1 天：Canvas 坐标和绘图基础

### 目标

把 Canvas 当成数学黑板，先能稳定画东西。

学习代码见：[01-canvas-coordinate-grid](D:/project/my-project/web-physics/00-canvas-math-visualizer/01-canvas-coordinate-grid/index.html)。

### 学习内容

- `canvas` 元素和 `2d` context。
- DPR 高清屏适配。
- 坐标系：原点、x 轴、y 轴。
- 画点、线、圆、矩形、文本。
- `clearRect()` 和重新绘制。

### 最小 Demo

做一个坐标网格：

- 显示中心原点。
- 显示 x / y 轴。
- 鼠标移动时显示鼠标坐标。
- 鼠标位置画一个点。

### 要解释的失败现象

- 为什么 Canvas 在高清屏上会模糊？
- 为什么浏览器窗口缩放后坐标会不准？
- 为什么 Canvas 的 y 轴方向和数学课里的坐标系相反？

### 完成标准

- [ ] Canvas 在高清屏下不模糊。
- [ ] 鼠标坐标显示正确。
- [ ] 能画出坐标轴、网格、点和文字。
- [ ] 能解释 Canvas 坐标系和数学坐标系的差异。

## 第 2 天：Vector 向量基础

## 第 3 天：三角函数、波和圆周运动

### 目标

把 `sin` / `cos` 从公式变成运动生成器。

### 学习内容

- `sin` / `cos`。
- 振幅、频率、相位。
- 圆周运动。

### 最小 Demo

- 支持调整振幅、频率、相位。

- 为什么相位变化会让波左右移动？

### 完成标准

## 第 4 天：Lerp、Easing 和平滑运动

### 目标

理解“从 A 到 B”不只是瞬间赋值，而是可以被设计的过渡。

### 学习内容

- `lerp(a, b, t)`。
- `inverseLerp(a, b, value)`。
- `clamp(value, min, max)`。
- 常见 easing：ease-in、ease-out、ease-in-out。
- 指数平滑：`current += (target - current) * factor`。

### 最小 Demo

做一个跟随实验：

- 一个点立即跟随鼠标。
- 一个点用固定时长 Lerp 跟随鼠标。
- 一个点用指数平滑跟随鼠标。
- 显示三者轨迹差异。

### 要解释的失败现象

- 为什么 `t` 超过 1 后会过冲？
- 为什么指数平滑永远不会真正到达目标？
- 为什么不同帧率下平滑速度可能不一致？

### 完成标准

- [ ] 能写出 `lerp`、`inverseLerp`、`clamp`。
- [ ] 能画出至少 3 种 easing 曲线。
- [ ] 能比较立即移动、线性插值和指数平滑。
- [ ] 能解释平滑运动和物理运动的区别。

## 第 5 天：Noise 基础

### 目标

### 学习内容

- Perlin Noise / Simplex Noise 的用途。
- frequency、amplitude、octave。
- 一维 Noise 曲线。
- 二维 Noise 灰度图。

### 最小 Demo

做一个 Noise 可视化器：

- 左侧显示随机曲线。
- 右侧显示 Noise 曲线。
- 支持调整 frequency 和 amplitude。
- 生成一张二维 Noise 灰度图。

### 要解释的失败现象

- 为什么随机曲线抖动很硬，Noise 曲线更自然？
- 为什么 frequency 越高变化越密？
- 为什么 octave 叠加后细节变多？

### 完成标准

- [ ] 能画出随机曲线和 Noise 曲线对比。
- [ ] 能调节 frequency 和 amplitude。
- [ ] 能生成二维 Noise 图。
- [ ] 能说清楚 Noise 适合模拟什么，不适合模拟什么。

## 第 6 天：Noise 流场和粒子

### 目标

把 Noise 从纹理升级成运动规则。

### 学习内容

- 用 Noise 生成角度。
- 用角度生成方向向量。
- 粒子位置、速度、加速度。
- 生命周期和轨迹。

### 最小 Demo

做一个 Noise 流场粒子：

- 网格上画出流场方向箭头。
- 粒子沿流场运动。
- 鼠标点击重置粒子。
- 支持显示 / 隐藏调试箭头。

### 要解释的失败现象

- 为什么直接用 Noise 值当速度会不好看？
- 为什么把 Noise 映射成角度后更像流动？
- 为什么粒子数量增加会明显影响性能？

### 完成标准

- [ ] 能画出流场方向箭头。
- [ ] 粒子能沿流场连续运动。

## 第 7 天：整合 Canvas Math Visualizer

### 目标

把前 6 天的小实验整理成一个可切换的学习工具。

### 功能建议

- Tab 或按钮切换模式：
  - 坐标网格。
  - 向量。
  - 波形。
  - Lerp / Easing。
  - Noise 曲线。
  - Noise 流场。
- 参数面板：
  - 振幅。
  - 频率。
  - 相位。
  - 插值系数。
  - 粒子数量。
  - 是否显示调试信息。
- 基础操作：
  - 暂停。
  - 重置。
  - 单步。

### 要解释的失败现象

- 为什么不同模式共用状态时容易互相污染？
- 为什么参数改变后需要重置部分模拟状态？
- 为什么调试显示会影响性能和视觉判断？

### 完成标准

- [ ] 至少整合 4 个模式。
- [ ] 每个模式都有一个可调参数。
- [ ] 每个模式都能显示至少一种调试信息。
- [ ] `notes.md` 记录每个模式解释的核心概念和失败现象。

## 阶段零之后

完成阶段零后，不要急着丢掉这些代码。后续学习中它会继续充当调试和对照工具：

- 学 Canvas 物理时，用它检查速度、加速度和力。
- 学 p5.js 时，用它对比 p5.js 帮你省掉了哪些样板代码。
- 学 Three.js 时，用它迁移 2D 向量直觉到 3D。
- 学 GLSL 时，用它对照 CPU 端和 Shader 端的坐标、时间、Noise。
- 学 PBD 时，用它画约束线、误差和迭代效果。
